# 진행 경과 패널

`mcp__progress-panel__progress_update` 는 앱 옆 패널에 작업 단계를 보여 준다.
작업 목록(update_plan)이 "무엇을 하고 있나"라면, 이 패널은 "얼마나 됐고 무엇이 남았나"를 숫자와 함께 남긴다.

## 언제 부르나

1. **시작할 때 한 번:** `reset: true`, `title`, 그리고 알고 있는 모든 단계를 `pending` 으로 올린다.
2. **단계를 시작할 때:** 그 단계만 `running`.
3. **단계가 끝날 때:** `done` + `detail`(한 줄 결과) + 해당되면 `freedGB`.
4. **막혔을 때:** `blocked` + `detail` 에 사람이 해야 할 일(예: "⌘Q 로 VS Code 종료 필요").
5. **사람이 할 일로 넘긴 단계:** `skipped` 가 아니라 `blocked` 로 두고 detail 에 명령을 적는다. 사람이 끝냈다고 하면 `done`.

## 자동으로 채워지는 것 (보내지 않는다)

- **경과 시간:** 패널 시작(`reset: true` 또는 첫 단계) 기준으로 30초마다 갱신된다. 모든 단계가 끝나면 마지막 완료 시각에서 멈춘다. 단계마다 시작·종료 시각도 자동으로 붙는다(`running` 으로 바꾼 때·`done`/`skipped` 로 바꾼 때).
- **단계별 모델·토큰:** 응답마다 그때 `running` 인 첫 단계에 모델별로 쌓인다(서브에이전트 포함). 그래서 **일하는 단계를 `running` 으로 정확히 바꿔 둘수록** 집계가 맞는다. 진행 중 단계가 없을 때 쓴 토큰은 '단계 밖'으로 따로 모인다.
- `freedGB`·`disk` 는 디스크 용량 작업에만 쓴다. 다른 작업에서는 보내지 않는다(패널에 용량 칸이 나타나지 않는다).

## 규칙

- 단계 `id` 는 짧은 영문 키로 고정하고, 같은 단계는 늘 같은 id 로 갱신한다(바꾼 필드만 보내면 된다).
- `label` 과 `detail` 은 사용자 언어로, 한 줄로 쓴다.
- `freedGB` 는 실제로 측정한 값만 넣는다(du·df 결과). 추정치는 detail 에 "약"을 붙여 쓴다.
- 확인하지 않은 일을 `done` 으로 두지 않는다.
- 디스크 공간이 걸린 작업이면 `disk: { beforeGB, nowGB, totalGB }` 를 보낸다(df 로 잰 값). 처음에 셋 다, 이후에는 `nowGB` 만 갱신하면 된다.
- 메모(`note`)는 판단이 필요한 사실(예: "Time Machine 스냅샷이 공간을 붙잡고 있음")에만 쓴다.
- 패널 갱신은 다른 도구 호출과 같은 메시지에 함께 보낸다. 패널만 갱신하려고 턴을 쓰지 않는다.

## 예

```json
{ "reset": true, "title": "디스크 정리",
  "steps": [
    { "id": "uv", "label": "uv 캐시", "status": "pending" },
    { "id": "vscode", "label": "VS Code 캐시", "status": "pending" }
  ] }
```

```json
{ "steps": [ { "id": "uv", "status": "done", "detail": "쓰지 않는 항목만 정리", "freedGB": 23.1 } ] }
```
